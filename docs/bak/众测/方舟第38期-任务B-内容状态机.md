## 完整 Prompt（直接粘贴方舟平台）

```text
你是 MisoTech 项目（Next.js 14 + TypeScript + Notion CMS + next-intl 双语）的 Application Owner Agent。
请严格按 `.harness/agents/application-owner.md` 定义的十阶段流程，交付以下需求。

================== 需求：内容草稿/发布状态机 + 定时发布 ==================

为博客内容引入「草稿 / 定时 / 已发布」状态机，并补一个内容管理后台与定时发布能力。具体：

1. 数据层（src/services/notion.ts）
   - 探明 Notion 博客库现有字段结构（阶段1 必须先读 notion.ts + 实查字段，不得臆断）。
     若 Notion 博客库尚无 status / scheduledAt 字段，在 spec 中列出需要用户手动新增的字段（HITL-1 决策点），
     并在代码中对字段缺失做防空处理（兼容旧数据：无 status 视为 published）。
   - 新增状态枚举：draft | scheduled | published。
   - 新增/改造查询函数：所有面向前端的列表（博客列表、搜索、sitemap、相关文章）必须只返回 status=published；
     提供 getPostBySlugWithStatus 供后台/预览使用。
   - 新增状态流转函数：setStatus(id, status)、setScheduledAt(id, ISO)。

2. 列表与详情过滤
   - 博客列表页（含 /zh 镜像）、搜索结果、sitemap.xml 不得出现 draft / scheduled 文章。
   - 博客详情页：draft 文章直接访问返回 404（对匿名用户）；scheduled 文章同样不可直接访问。
   - 作者草稿预览：新增 /api/content/[id]/preview?token= 端点，校验 token 后返回草稿渲染数据；
     token 由服务端按 postId+秘钥生成，未配 PREVIEW_TOKEN 时降级为控制台打印 token。

3. 定时发布
   - 新增 /api/cron/publish?secret= 端点（Edge 或 Node 均可）：扫描 status=scheduled 且 scheduledAt<=now 的文章，
     逐篇转 published，失败隔离（单篇失败不影响其他），返回 {processed, failed, skipped}。
   - secret 读 CRON_SECRET，未配置时端点拒绝运行（返回 401）并提示需配置。
   - 提供 vercel.json 的可选 Vercel Cron 配置示例（每天/每小时触发一次）；本地不依赖真实 cron，
     用 curl 手动触发 /api/cron/publish?secret=xxx 验证。
   - 转为 published 后调用 /api/revalidate 钩子刷新受影响路径（blog 列表 + 该文章详情 + 双语）。

4. 内容管理后台（/admin/content，复用现有 /admin 体系，已有 /admin/notify）
   - 列出全部文章（含 draft/scheduled/published），显示状态标签、scheduledAt、createdAt。
   - 支持改状态（draft<->scheduled<->published）、设置/清除 scheduledAt。
   - 调用上面第 1 点的状态流转 API 与第 3 点的 cron 触发。
   - admin 页与状态标签文案走 next-intl（en/zh），深色模式 + 移动端适配。
   - admin 路由需校验 ADMIN_TOKEN（未配置时仅允许本地访问并控制台告警，不抛错崩溃）。

5. 触发与 ISR 联动
   - 改造 /api/revalidate：支持在状态变更后按 path 批量 revalidate（blog、blog/[slug]、/zh 镜像）。
   - REVALIDATE_SECRET 未配置时端点拒绝运行（沿用现有约束）。

6. 单元测试（阶段 5 走 A 路径，必须做）
   - 引入 vitest：装依赖、写 vitest.config.ts、改 package.json 的 test 脚本为真实跑测（替换现有 exit 0 占位）。
   - 用 TDD 红绿重构，至少覆盖：
     a) 状态过滤：draft/scheduled 不出现在 published 列表（含旧数据无 status 兜底为 published）；
     b) cron 发布：scheduled+scheduledAt<=now 转 published，未来时间不转，单篇失败隔离；
     c) 预览 token 校验：无 token / 错误 token / 正确 token 三态；
     d) 状态流转 API 的输入校验。
   - 不得虚构测试通过——npm test 必须真实跑通且 total_tests>0，输出贴进 ci_result.md。
```

## 本地验证步骤

### 准备
```bash
# 在 git bash 中
npm install            # 装新依赖（vitest 等）
# .env.local 追加（见下方环境变量）
npm run dev:env        # 端口 4000
```

### 「有 Key」全链路验证
1. Notion 博客库手动加 `status`（select: draft/scheduled/published）与 `scheduledAt`（date）字段。
2. 建一篇 status=draft 文章 -> 访问 `/blog` 看不到 -> 直接访问 `/blog/[slug]` 返回 404。
3. `/admin/content` 设该文章 scheduled + scheduledAt=过去时间 -> curl `/api/cron/publish?secret=xxx` -> 状态转 published -> 列表出现 -> revalidate 生效。
4. 草稿预览：`/api/content/[id]/preview?token=` 返回草稿内容。
5. `npm run lint && npm run build && npm test` 全过。

### 「无 Key」降级验证
1. 清空 CRON_SECRET / PREVIEW_TOKEN / ADMIN_TOKEN。
2. cron 端点拒绝并提示；预览端点降级打印 token；admin 本地放行 + 控制台告警。
3. 旧数据无 status 字段 -> 兜底为 published，列表正常。
4. curl 手动触发 cron 端点验证（用临时 secret 或本地放行模式）。
5. 全程无报错，页面不崩。

### 示例环境变量
```bash
# .env.local 追加
CRON_SECRET=your_cron_secret           # cron 端点鉴权
PREVIEW_TOKEN=your_preview_token       # 草稿预览鉴权（不填则控制台打印 token）
ADMIN_TOKEN=your_admin_token           # admin 路由鉴权（不填则仅本地放行 + 告警）
REVALIDATE_SECRET=<已有>               # 复用现有
# Notion 博客库需手动加字段（非环境变量）：
#   status      (select: draft / scheduled / published)
#   scheduledAt (date)
```
